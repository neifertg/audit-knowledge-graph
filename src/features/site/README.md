# site

Purpose: the public page (E4), a static site rendered in Python from committed exports, so every figure on it is traceable to its source and checked by a test.
Entry point: `build.py` (`python -m src.features.site.build --out <dir>`); `export.py` for the site data.
Owns: `data/site.json` (the blast-radius subgraph, the story counts, the measured symmetry table) and the page's template, CSS and JS.
Depends on: `src/features/rounds/rounds.json`, `src/features/reconciliation/scores.json`, `src/features/rounds/symmetry.py`; the export also reads a loaded build's `akg.sqlite` (read-only).

Notes for people and agents working here:
- **Build and preview.** `python -m src.features.site.build --out <dir>` writes `index.html` (the planning brief) and `methods.html` (scoring, queries, appendix) and copies the CSS, JS and the three JSON files beside them. It reads only committed files, never a build or database, and uses the standard library only, so it runs in CI and in the Pages workflow. Preview with `python -m http.server` inside `<dir>`, then open the printed address.
- **Regenerate the site data** after a change to the rounds, the reconciliation or the generator: `python -m src.features.site.export --out <loaded seed-42 build>`. A test fails while `data/site.json` is stale. It never reads the answer key.
- **Every figure is rendered in Python, marked with its source.** In `template.html`, `{{<source>|<format>}}` becomes `<span data-source="<source>" data-format="<format>">text</span>`. A source is `site.json:<path>`, `rounds.json:<path>`, `scores.json:<path>` or `derived:<name>.<path>`; a path uses dots, `[i]` and `[*]`; several sources may be joined by commas for a formatter that takes a list. Formatters live in `formatters.py` (`plain`, `count_word`, `count_word_cap`, `times_word`, `signed`, `fraction`, `rows_shown`, `names_and`), each unit-tested; derived figures (verdict counts and the like) in `derived.py`, which the test recomputes independently.
- **No figure is typed.** A test takes the rendered page's visible text minus every marked element and allows only a short list of literal tokens (`60`, `1.25`, `M1`, `M2`, `L1`); any other digit, or a number word (`one` to `twenty`, `dozen`, `half`, `once`, `twice`, case-insensitive), fails it. To add a figure, add a placeholder, never the number.
- **site.js holds no digit at all**, and does not fetch or write text into the page: colours and sizes come from CSS custom properties in `site.css`, and the graph's data from the embedded `<script type="application/json" id="site-data">`, which a test compares with `site.json`. The canvas shows only names.
- **Copy rules.** A test holds the brief's fixed text, so an edit to that copy is an edit to the test. The page must say the data is synthetic and the text AI-written, label owner concentration as derived, say the graph informs judgment and does not score risk, and keep speed words inside the element marked `data-disclosure="no-speed-claims"`. Names come only from the data (INV-9; the generator's denied-name list is checked on the page).
- **The one external resource** is Cytoscape.js 3.34.4 from cdnjs, on the brief only, loaded with its SRI hash; nothing else is fetched. The methods page loads no external resource.
- **The brief and the methods page.** `index.html` opens with the executive summary under the H1 (a hook, four findings and a footnote, word for word the same as the README's, pinned by `EXECUTIVE` in the tests; every figure is a placeholder). Then a single synthetic note (the only `data-disclosure="synthetic"` on the brief) and a pointer (`data-statement="kg-pointer"`) to the knowledge-graph explainer, which opens 'Supporting evidence' (`id="what-is-a-knowledge-graph"`, `data-statement="kg-explainer"`) directly before the 'Graph or SQL?' story; the explainer must name the relational store's link tables and carries no figure (change 025). Below that it is the planning brief (shared-warehouse coverage, repeat findings, owner concentration, fourth-party exposure, stale high-risk coverage, year-over-year findings, the SQL comparison, and the review queue). `methods.html` has `#rounds`, `#operating-model` and `#appendix`: every round from `rounds.json` (questions, both queries, scores, margins, measured verdicts, checks, the first rows, truncation notes), the verdict rule, the measured symmetry table, the shared views, measured results, and the data model (`site.json`'s `inventory`), generator, reconciliation accuracy, tests, limitations and how to reproduce. The expected-verdict line and the closed-epic counts are not rendered.
- **Labels on the methods page, each tested.** `data-label="measured"`: sentences that state measured results only, naming their rounds through derived figures whose rules the test recomputes. `data-label="practice"`: advice from building the project, shown with "practice, from building this project". The `expected-not-measured` label is not published; claims the rounds did not measure are omitted rather than shown as findings. A new claim goes in the paragraph that matches what backs it.
- **Publishing** (change 023): `.github/workflows/pages.yml` builds this page from the committed files after the tests pass on main and deploys only that tested commit while it is main's head; see `docs/pages.md`.
