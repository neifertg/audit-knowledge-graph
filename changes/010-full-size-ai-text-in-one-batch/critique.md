VERDICT: REVISE
1. [major] The budget arithmetic holds, but the budget gate has holes and its named test may not exercise the cumulative part. Arithmetic: claude-opus-5-5 costs $4/$20 per MTok, and batches are 50% off, so $2/$10. 971 input x $2/M + 199 output x $10/M = $0.00393 per item. 1,274 items x $0.00393 = $5.01 per pass. That leaves about $5 for resubmissions and one or two files: control_ia (395 items) is about $1.6-2.4 even if its output tokens double. The plan's statement "does **not** cover a second complete pass" is correct. The gaps are these:
   (a) AC-1 counts "spend already logged in ... cost_log.md", and spend is logged only "on collection". A batch that is submitted but not yet collected therefore counts as $0. Two submissions made before the first collection both pass the check (for example, a re-run because the first looked stuck), and the account is charged for both.
   (b) `cost_log.md` does not exist yet (research/r2-synthetic-text-realism holds only decision.md and sample_pack.md). The plan does not define the format the script parses, what a missing file means, or what happens on a line it cannot parse. If a parser skips lines it does not understand, the gate fails open.
   (c) The cap compares estimates. With `max_tokens=4000` (the current `_rewrite_once`), actual output can far exceed 199 tokens per item, so actual spend can cross $10 after a run passed the check.
   (d) The test description says "refusal touches neither secrets nor client". An implementation that ignores the log entirely passes this whenever the test's estimate alone exceeds the budget.
   -> Record each submission's estimate in the log at submit time and replace it with actuals on collection, so uncollected batches count. Define the log line format: a missing file means $0, and an unparseable line refuses (fail closed). Set a stated per-request `max_tokens` and say that actual cost can exceed the estimate by at most that bound. In AC-1's test, use a log showing about $6 spent plus a $5 estimate under a $10 budget, so the run is refused only because of the log, and add a case where the same estimate with an empty log is accepted.
2. [major] The prompt-revision path conflicts with L-002, and the plan does not say so. Data impact says the cap covers "regenerating one or two files after a prompt revision". L-002 says "regenerate the whole set after any prompt change so all text shares one prompt", and the budget cannot cover a whole set a second time. Nothing detects mixed prompts either: `input_hash` covers only the templated inputs (`_hash(file, key, title, desc)`), not the system prompt or voice, so text from two prompt versions would pass every check. -> State the rule: a revision may change only that file's `VOICE` entry, and that file is regenerated in full. A change to the shared `system_prompt()` means a whole-set regeneration and needs a fresh owner approval. Either include the prompt and voice in each entry's hash or record a prompt-version field that check-text compares. Also update R2 decision.md's "the cap covers one prompt revision plus resubmissions" to match, since it is in areas.
3. [major] The re-measured cue numbers have no test that can fail. AC-5 says "the cue measurements docs/data-model.md publishes (control citation lookups, the repeat-finding finding-sentence cue) are re-measured on AI text and updated". None of the named tests computes them. test_controls AC-5 only caps `subject_kind_f1 <= 0.80` and `title_in_description_f1 < 0.5`. test_issues AC-4 (a) only caps exact-description grouping at 0.5, and AI text, where every description is unique, passes that trivially. No test computes the "strip the four openings, group by the rest" figure (recall 1.0, precision 0.36). The data model could keep stale or wrong numbers while the whole suite is green, which O2 ("no claim without a test or a cited method") forbids. -> Add the measures as helpers in tests/generator/difficulty.py (whole title in text, subject phrase plus type, plus the kind map, opening-stripped finding grouping). Add a named test that computes them on the default full build and asserts each published figure within a stated rounding. Without such a test, a change to the text or the generator leaves the page wrong and the suite still green.
4. [minor] The `--count` rule, as worded, still breaks two drift tests. AC-5 says "`--count` overrides at full size ... build with `--text templated`". But `test_issues.test_ac7_person_count_leaves_other_files_unchanged` and `test_full_build.test_ac6_child_a_checks_hold_at_full_size` compare checksums of `build(*FULL)` (now AI) with the override build (templated). Every description file then differs and the drift assertion fails. PERSON and REGULATION overrides change no text keys or hashes, so they could keep AI text. -> Decide whether these overrides keep AI text (both sides AI) or both sides use templated. Name the two tests in AC-5. If templated, note that the independence check then no longer covers the shipped text.
5. [minor] AC-2 and AC-3 each name a single test for several rules, and nothing requires a failing fixture per rule. A permissive rule function passes both AC-3 and AC-4's "the committed file passes the AC-3 rules", because both use the same code. -> State that AC-3's test feeds one violating item per rule (added system, a two-sentence or 31-word ERM control, a changed issue opening, a deny-list name, a stray capitalized word) and asserts each is rejected with its reason. State that the AC-2 fake results file holds one each of `errored`, `expired`, `canceled`, `refusal`, `max_tokens`, an unknown custom ID and a missing one, and that the test inspects the request params for absent `fallbacks`, `stream` and `speed`, and the custom-ID pattern `^[a-zA-Z0-9_-]{1,64}$`.
6. [minor] `test_ac6_tests_never_import_anthropic` can pass while the batch tests import it. `write_text.main` does `import anthropic` before any work, and the package is installed in the venv. A source grep of the test modules would pass even though calling `main()` with a fake client loads the SDK. -> Make it a runtime check: run the batch tests in a subprocess and assert `"anthropic" not in sys.modules`, the same pattern as test_offline's GUARDED_BUILD. Or require the batch code to take the client (or a factory) as a parameter and import `anthropic` only in the real factory.
