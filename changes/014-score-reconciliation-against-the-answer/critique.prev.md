VERDICT: REVISE
1. [major] The orphan caveat is reworded so that it contradicts the epic and is inaccurate. AC-3 has "orphan controls ... always score as unmatched, which is structure, not matcher skill (pair figures exclude them)", and AC-1 has "true non-matches, including orphans, cannot inflate them". The epic's contract text is "always score as 'unmatched', which helps the figures and is not matcher skill". Orphans are not excluded: `features.control_table` puts every control into the 118,105 candidate pairs, and an orphan's `risk_link` is 0 (`default=0.0`, features.py:126). So orphans are easy negatives. Precision and recall don't count true negatives, but orphans still help precision, because they almost never become false merges or queue rows. That is the help the epic asks the page to admit. -> Keep the epic's wording ("helps the figures, not matcher skill"), drop "pair figures exclude them", and add one AC-1 figure that makes the help visible: orphan controls appearing in merged pairs and in queue rows (the expected value is about 0, and that near-zero is the give-away).
2. [major] AC-3's exact-equality test includes a fresh retrain, so it can differ between platforms. "A test re-scores the cached seed-42 build and asserts the result equals the committed file exactly". Per AC-3, that file holds "every AC-1 and AC-2 figure", and AC-2's figures come from refitting the control model on seed 7 at test time. The epic explicitly says retrained floats differ between Windows and Linux, and it compares weights to 1e-6 and thresholds "by the training pair it selects rather than by its value" (test_matching.py:89-90). The committed JSON will be generated on Windows and checked on Linux CI. The AC-1 figures are safe, because they come from the reconciled output, which INV-7's golden makes byte-identical. The ablation counts are not: a threshold or score within about 1e-6 of a boundary flips a count. -> Choose the ablated thresholds by their training pair, as `weights.json` does, and compare the ablation ratios within a tolerance (counts exact). Alternatively, commit the ablated model's entry and score from it, with a 1e-6 currency check like the existing retrain test.
3. [minor] The figures depend on definitions that exist only in a scratchpad script (`e2d_measure.py`), which is ephemeral. The plan's prose ("scored on the final canonical pairs", "raw accept-band figures before conflicts", "recall reached if a reviewer resolves the queue correctly") doesn't pin these definitions:
   - a control true pair is an ERM x IA pair in one non-`none` cluster, with IA-IA pairs not scored;
   - a merged pair is an ERM x IA pair sharing a canonical ID;
   - queue pairs are (`item_a`=ERM, `item_b`=IA), and duplicate pairs are ordered by ID;
   - raw accept = merged plus `conflict` rows;
   - resolved recall = (true merged + true queued) / true pairs;
   - "missed" means not merged and not queued in AC-1, but band `below` in AC-2.

   -> Add these definitions to the plan or to the AC-5 docs section, so a data scientist can reproduce the figures from the text (O2), and build the AC-1 mini build to exercise each one: an IA-heavy control cluster, a conflict row, an orphan, a misfiled risk, an unmapped node, and a duplicate pair.
4. [minor] The epic asks for "taxonomy mapping precision and recall per level". AC-1 gives "correct per level" (accuracy) plus "falsely unmapped". Because the mapper can output `unmapped`, precision (correct among mapped) and recall (correct among truly mapped) differ from accuracy. -> Either report precision and recall per level, or state in the plan that accuracy plus falsely-unmapped is a deliberate substitute for the epic's wording.
