Today `ISSUE_TEMPLATES["IA"]` is `("{ia_title} not operating as designed", "{finding}")`. On the current full build every IA issue title contains its control's full IA title word for word, and every IA issue's description equals that control's `finding` exactly. Four templates still put the same `{ia_title}` in every title, and the description stays identical across a group. So `GROUP BY description`, or a match on the control title inside the issue title, finds every repeat group without the graph. That undoes "repeat findings filed under different names", which is the M1 story and the premise of the E3 round. Child f will not fix it: issue AI text replaces only the `description` column (`TextItem(..., "description", ...)`), so titles stay templated for good. The plan's L-008 line ("no new shared text vocabulary across sources here; issues are not cross-source matched") skips the point that L-008 applies to within-source matching too. -> Follow L-008. Add the exact-phrase lookups as measures in AC-4(a): exact description equality, and the control title inside the issue title, each scored against the planted groups (for example recall at or below 0.5). Then either vary the title and description wording across a group (wording from the finding, not the control title; the description varying per issue), or have the owner accept the cue as realistic and document it in docs/data-model.md, as 008 did.
