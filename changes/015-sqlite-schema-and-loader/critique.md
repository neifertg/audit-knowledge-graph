VERDICT: REVISE
1. [blocker] The load step breaks `reconciliation.test_matching.MatchingTests.test_ac2_committed_weights_are_current`, and the fix is outside `areas`. The plan says "build runs generate, reconcile, then load, writing `<out>/akg.sqlite`". But `train.build_training_bank` runs a plain `akg build` (no `--no-load`), and `train.fingerprint` hashes every file under the bank (`bank.rglob("*")`). So the fresh training bank gains `akg.sqlite`, its fingerprint no longer equals `weights.json["fingerprint"]`, and the test fails. Fixing it means editing `src/features/reconciliation/train.py` (adding `--no-load` to `build_training_bank`, or leaving `akg.sqlite` out of the fingerprint; either keeps the committed fingerprint valid). That folder is not in `areas`, and regenerating `weights.json` would contradict "no golden changes". -> Add `src/features/reconciliation/train.py` to `areas` and name the fix in the plan. Do not touch `weights.json`.

[major] The plan says "Nothing in E1's or E2's outputs changes, and no golden changes", but the generator goldens break. `tests/generator/golden.checksums` leaves out only `reconciled/`. `test_determinism.test_ac3_inv7_output_matches_golden_checksums` (sample) and `test_ac5_full_build_matches_full_golden` (full) both run a plain `akg build`, so after this change their checksum dict includes `akg.sqlite`, which neither golden lists. -> Pin the fix: either `checksums()` leaves out `akg.sqlite` (it is derived, per the epic), or those tests pass `--no-load`. Add a criterion or test line that shows both golden tests still pass unchanged.
3. [major] The L-014 count is wrong: "the suite gains one load (under a second) rather than one per test". Counting the plain `akg build` callers, each gains a load once this lands: `test_determinism` (2 sample and 2 full builds), `test_issues.py:65` (full), `test_canonical.py:52/61` (sample), `test_ai_text.py:27`, `test_batch.py:249`, `test_offline.py:33`, and the training bank in `test_matching` (full). That is about 10 loads, or roughly 6-10 s at the measured 0.6-0.7 s each. The cost is small. The miscount matters because those uncounted callers are where issues 1 and 2 come from, which is exactly what L-014 warns about. -> List every build caller and say for each whether it loads or passes `--no-load`, then restate the added suite time.
4. [major] AC-2's type rules cannot express the reconciled columns. (a) There is no rule for decimals: `logit` (maps-to files and the review queue) and `score` (`ia_maps_to_erm`) are 6-decimal numbers, and the dictionary format has only id/text/enum/int/date. As written they would become TEXT, so later rounds would sort and compare them as strings. (b) Under "A value naming `x.csv` becomes a FOREIGN KEY", the natural dictionary entry for the either-source columns ("`risk_erm.csv` or `risk_ia.csv` (by `source`)", which is how the generator's answer-key dictionary writes it) does get a FOREIGN KEY, to the first file named. (c) "NOT NULL unless its values mention `blank`" conflicts with "`ia_maps_to_erm.erm_node_id` is a nullable FOREIGN KEY, holding NULL for `unmapped`", because the CSV holds the literal `unmapped`, not a blank. That makes it a hard-coded special case the AC-2 fixture never exercises. Blank `logit` cells on singleton rows also need the dictionary to say "blank". -> Add to AC-2: a `real` type that becomes REAL; a value naming two or more files gets no FK; and a dictionary convention for "token X loads as NULL" (for example "`unmapped` (loaded as NULL)"), with the NOT NULL rule honouring it. Cover all three in the AC-2 fixture.
5. [major] Missing criteria for stale and partial stores. The epic says the store is derived, and 013 set the precedent that `--no-reconcile` "removes any stale output". Nothing says what happens to an existing `<out>/akg.sqlite` after `build --no-load`, `build --no-reconcile` or `akg reconcile`. A stale database would silently feed `akg rounds` in children c and d. The plan also does not say what `akg load` does when `reconciled/` is missing, or whether a failed load (a CHECK or FOREIGN KEY error) leaves a half-written `akg.sqlite`. -> Add: these paths remove a stale `akg.sqlite`; `akg load` without `reconciled/` exits non-zero with a clear message; a failing load leaves no `akg.sqlite` (write to a temp file, then rename). Test each in AC-4.

[minor] AC-3's cross-source check does not cover the review queue: "Every cross-source reference in the reconciled tables exists in the table its `source` names". `review_queue` has no `source` column; its `item_a`/`item_b` tables depend on `kind` (risk: ERM risk and IA risk; duplicate: ERM and ERM; control: ERM control and IA control). -> State the kind-to-table mapping, and give `ia_maps_to_erm` an explicit `primary key` on `ia_node_id` instead of a composite key over a nullable column.
7. [minor] AC-3's "the set of row tuples equals the CSV's" uses sets, so it would pass a loader that silently drops duplicate rows (`INSERT OR IGNORE`). It also does not say how INTEGER/REAL values are compared with CSV strings. -> Compare multisets (or sets plus row counts), and pin the normalisation: values cast back to their CSV text form.

Re-measure the 5 s bound with FKs on.
