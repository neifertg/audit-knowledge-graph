VERDICT: REVISE
1. [major] AC-1 and AC-7 disagree on the file layout for risks and controls. AC-1 says the build "writes one CSV per entity type" (one `risk.csv`, one `control.csv`, each with a `source` column, as in the data model), and the Data impact section repeats "one CSV per entity". AC-7, however, asserts that "the order of matched clusters in the ERM CSV differs from their order in the IA CSV", and the epic says "IDs and row order shuffled independently per source". Both of those assume separate ERM and IA files. If the implementer picks a single file, AC-7's order check has nothing to compare and has to be reinterpreted. If they pick per-source files, AC-1's "1-20 rows" limit and its file-count rule no longer describe the output. The choice is expensive to undo, because the golden checksums (AC-3), the data dictionary (AC-9), the files b-e extend and E3a's schema all depend on it. It is also a realism question for the pack, since ERM and IA keep separate systems. -> Pick one layout in the plan and use it in AC-1, AC-7, AC-9 and Data impact. For example: "RISK and CONTROL are written per source (erm_risk.csv, ia_risk.csv, ...), each 1-20 rows". Or, with a single file, restate AC-7's order check as "the relative order of matched clusters among ERM rows differs from that among IA rows".
2. [minor] The `--text ai` case added to AC-7 is mostly vacuous, so AI-text leakage can still reach the R2 decision unchecked. Of AC-7's checks, "their descriptions share no full template sentence" cannot fail on AI prose, because AI text contains no template sentences. The ID, attribute and order checks do not depend on the text variant. AC-2's hard-negative cosine also runs only on the default (templated) build. AI text is written from each item's template inputs, and matched items share a concept, so the two descriptions can come out as near-paraphrases. The owner could then choose AI text on the strength of this pack, and c and d would find the leak only at full size. The last critique (item 6) suggested a cosine ceiling, and it was not adopted. -> For `--text ai`, assert something that can fail. For example, no matched pair's TF-IDF cosine exceeds a stated ceiling, or run AC-2's hard-negative computation on the AI descriptions as well.
3. [minor] AC-4 depends on an artifact that the Gate hand-off creates only after every criterion passes. AC-4's when-clause is "the sample build, the committed AI text and the sample pack exist", and it scans "sample_pack.md". The Gate hand-off says `sample_pack.md` "is committed with the change" "when every criterion passes". If AC-4 reads the committed file, it cannot pass before the file exists, which makes the order circular. A stale committed pack would also hide a regression. -> State that AC-4 generates the pack to a temp path, as AC-8 does, and scans that output.
4. [minor] The tests could be silently skipped by the project's own done-check. The test command is `python -m unittest discover -s tests`. On Python 3.11 and later, `discover` no longer recurses into namespace packages, so if `tests/generator/` has no `__init__.py`, every AC-1 to AC-9 and AC-11 test is skipped while the run still reports OK. The named tests also use pytest's `file::function` form, but unittest needs `TestCase` classes, so the names as written don't map onto anything the runner reports. -> In the Test plan, say that `tests/generator/` is a package and that the tests are `unittest.TestCase` methods. Also say that "done" means each named test shows up in verbose output (`-v`), not only that the overall run is green.
5. [minor] AC-10's "a declared dependency of one" is ambiguous about depth, and a one-level reading fails on the real dependency tree. Several required pins are transitive two or more levels down: `six` (via python-dateutil under pandas), `h11` (via httpcore and httpx under anthropic), `pydantic-core` (via pydantic under anthropic). If the test checks only direct dependencies of the approved packages, it rejects a correct requirements.txt. -> Say "in the transitive dependency closure of an approved package", computed recursively from `importlib.metadata.requires`, ignoring extras and environment markers that don't apply.
