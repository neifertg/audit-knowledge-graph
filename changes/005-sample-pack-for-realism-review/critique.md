1. [major] No criterion checks that relationship files point at real rows, including the new cross-source rule. Data impact adds "**New rule: no relationship crosses sources.** ... Added to `docs/data-model.md` in this change", but no criterion tests it. AGENTS.md says "each invariant in `docs/data-model.md` gets one" test, and rule 6 makes the data model binding. More broadly, AC-1 checks only that "every relationship CSV has at least one row", and AC-2's "every referenced ID exists" covers answer_key/ only. So a build that passes every criterion could still produce any of these: an IA risk ID in `control_mitigates_risk_erm.csv`, an issue owner missing from `person.csv`, or an `audit_tested_control_ia.csv` row pointing at an ERM control. The owner would also review a pack containing broken links. -> Add to AC-1, or as a separate criterion with a named test: every ID in every relationship CSV exists in the entity CSV its file name names, and in a source-suffixed file it exists in that source's file. If the cross-source rule goes into the invariants table, name this test there.
2. [minor] AC-11 can pass without proving anything, and the plan does not say which stream draws the edges. (a) The criterion uses "`--count REGULATION=5`", but the plan never fixes the sample's default regulation count. If the default is 5, the two runs are identical and the test proves nothing. (b) Data impact says "Random streams are sub-seeded per entity type", but `requires`, `mitigates` and other edges are not entity types. If `requires` edges are drawn from the CONTROL stream, a different regulation count changes how many draws `random.choice`/`_randbelow` consumes from that stream. That alters `control_erm.csv`, so AC-11 fails on a design that follows the plan as written. The same coupling would let d's or e's new edges change earlier output, which is the epic's real concern. -> In AC-11, have the test assert that the varied count differs from the default. In Data impact, say that each relationship file draws from its own sub-seeded stream (seed derived from the master seed and the file's base name), or that edges are drawn only after, and separately from, every entity attribute draw.
3. [minor] Two gaps remain in AC-4 (INV-9). (a) The test finds name columns from "every column the data dictionary marks with `name_list: <list>`", but no criterion requires any column to be marked. If the person name, system name or vendor columns are left unmarked, the list check silently skips them and AC-4 still passes. AC-9 checks only that columns are listed with type and allowed values. (b) The AI-text proper-noun check covers only "every run of two or more capitalized words", so an invented single-word vendor or system name in AI text ("migrated to Corevance") passes unless it happens to be on the deny-list. -> (a) Have AC-4 assert that a fixed set of columns is marked, at least person name, system name and any vendor or institution column. (b) Apply the allow-list check to every capitalized token that is not sentence-initial, not just runs of two or more; put acronyms such as SOX, BSA/AML and KYC on the allow-list.
