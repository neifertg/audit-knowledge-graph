VERDICT: REVISE
1. [major] The timebox's fallback contradicts the criteria and the epic's gate. The timebox says: "If slices 1-5 take more than 1.5 days, cut slice 6 (AI text) into its own change and show only templated text in the first pack." AC-6 and the AI-text part of AC-4 need committed AI text, and AC-8 requires "templated and AI descriptions side by side". So after the cut, three criteria cannot pass and the change cannot finish. Under rule 1, changing an approved plan needs `capitan revise` and another round of critique and approval. The cut also leaves R2 undecidable at the gate, because R2's question is templated vs AI and the epic says the pack shows both. The owner would then have to review twice. -> Say what the cut actually means. Either (a) the cut is a `capitan revise` that moves AC-6, AC-4 (AI part) and the AI half of AC-8 into a new child, and R2 stays open until that child's pack is reviewed, or (b) there is no cut: AI text stays in a, and the timebox is extended or a different slice (for example AC-9) is deferred.
2. [major] Slice 6 has no approved way to read `~/.claude/secrets.yaml`. The Test plan says `write_text.py` reads the key "at runtime from `~/.claude/secrets.yaml`". The standard library has no YAML parser, and none of the approved packages (`neo4j`, `networkx`, `scikit-learn`, `pandas`, `anthropic`) or their dependencies installs one. AC-10 also requires every line of requirements.txt to be an approved package. The implementer would have to stop for the owner's OK in the middle of the timebox, or hand-roll a fragile parser. -> Decide it in the plan. Options: get the owner's OK for PyYAML as a script-only dependency kept out of requirements.txt (and say so in AC-10); use a minimal parser for one key path, with a test; or have the owner bridge the key into an env var for that one run.
3. [minor] The Risks section relies on something no criterion produces. It says the deny-list is "backed by the owner's one-time review of the name lists in the pack", and the epic requires that review in a. AC-8, however, only requires entity rows, text variants and a per-entity-type review table. A pack that leaves out the name lists, or has no names row in the review table, passes AC-8. -> Add to AC-8: the pack lists every name list in `src/features/generator/names/`, and the review table has a "names" row.
4. [minor] AC-4's whole-token, case-insensitive deny-list scan collides with ordinary audit words. Real bank names include "Key", "Regions", "Citizens" and "Comerica", and vendor or core-system names include "Oracle" and "FIS". A scan that matches the token "key" fails on "key control" in templated control text, which is guaranteed to appear, since controls carry a key flag. The implementer then either drops these names, which quietly weakens INV-9, or fights the test. The scan also cannot catch a fictional name that merely resembles a real one, which is a non-goal. -> Specify that deny-list entries are distinctive forms ("KeyBank", "KeyCorp", "Regions Financial", "Citizens Financial Group") or allow multi-token entries, and state that resemblance is left to the owner's name-list review (issue 3).
5. [minor] AC-7's row-order assertion can be vacuous or impossible, and AC-2's coverage minimum is too low to support it. AC-2 requires only "at least one cross-source risk match, cross-source control match". With one matched cluster, "the order of matched clusters in the ERM CSV differs from their order in the IA CSV" cannot hold. With two, a fixed seed decides it by luck. AC-2's hard negative is also "at least one" across both types, while the epic runs leakage and hard-negative tests "separately for risks and for controls". -> Require at least 3 cross-source clusters each for risks and controls in AC-2. Assert one hard negative for risks and one for controls. In AC-7, compare the rank order of matched clusters (not equal, and not reversed).
6. [minor] Only the templated variant is checked for leakage, determinism and offline running, yet the owner may pick the AI variant on the strength of this pack. AC-3, AC-5 and AC-7 all run at default settings. AI text generated from each item's template inputs can come out near-identical for matched ERM and IA items, which leaks the answer key. Then R2 would pick a variant that c and d later find unusable. -> Add AI-text cases: AC-5 also runs with `--text ai`, and AC-7 (or AC-2's cosine computation) also runs on the AI descriptions, asserting matched pairs are not near-duplicates (for example, cosine below a stated ceiling).
7. [minor] AC-10 forbids pinning transitive dependencies, so the bytes that AC-3 checks can drift. AC-10 says "every line is an exact pin ... of a package on the approved list", which leaves numpy (under pandas and scikit-learn) unpinned. If the generator draws from numpy's RNG or writes through pandas `to_csv`, a numpy or pandas upgrade can change output and break the golden checksums for a reason unrelated to the code. -> Either state that the generator uses only the standard library `random` and `csv` (scikit-learn and pandas are used only in tests), or allow exact pins of transitive dependencies in AC-10.
8. [minor] Two mechanisms in the criteria are unnamed, so the tests cannot be written against a stable hook. First, AC-4's "every name column" doesn't say how the test finds name columns. Second, AC-6's "the orphan check fails naming the key (extra)" doesn't say what the orphan check is or how to point it at a temp text dir. -> Have AC-9's data dictionary mark name columns with their source list, and have AC-4 read that marking. Name the orphan check as a callable function or command that takes `--text-dir`.
9. [minor] AC-9's scope is ambiguous. "every CSV and column in the output" doesn't say whether `answer_key/` files belong in the data dictionary. One implementation can document them and another skip them, and both pass. -> State it either way. The epic says E3a builds its schema from the dictionary, which suggests answer-key files are documented separately or marked as not loaded.
Not checked: whether `python -m akg` at the repo root can import `src/features/generator` without packaging files outside the areas (for example `pyproject.toml` or `src/__init__.py`); whether the deny-list content is adequate; whether ~15 rows are enough for the owner to judge realism (a manual gate by design). All ten items in critique.prev.md look addressed in this revision.
