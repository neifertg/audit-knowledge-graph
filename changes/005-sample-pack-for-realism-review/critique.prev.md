VERDICT: REVISE
1. [major] AC-11 would still pass with a broken implementation. The criterion reads "the build runs with seed 42 and `--count ISSUE=5` ... every CSV whose file name does not start with `issue` ... is byte-identical", and it is meant to prove that "per-type random streams are independent". ISSUE is almost certainly the last type generated, because issues depend on audits, controls, risks and people. With a single global `random.Random(seed)`, changing the issue count changes no draw that comes before the issues, so the test passes without any per-type streams. The epic's actual threat runs the other way. When b-e add draws to a type that is generated early (b: org and taxonomy, c: risks), a global stream shifts every later type's output, and the golden checksums then change for reasons unrelated to the change. -> Vary the count of a type that is generated early and has few dependents, for example `--count REGULATION=N` or `--count SYSTEM=N`. Assert that every file that does not involve that type (its entity file and its edge files) is byte-identical. Or say in the criterion that the varied type must be generated before at least half of the other types.
2. [minor] The file-layout rule conflicts with the epic's audit-scope rule for `tested`. AC-1 says relationship files are "split by source wherever one end is a sourced entity" and that "every relationship CSV has at least one row". The epic says "Audits test IA controls only ... ERM controls are never in `tested`". Read literally, AC-1 requires an `audit_tested_control_erm.csv` with at least one row, which breaks the epic's rule. If that file is left out instead, the Data impact rule as written does not describe the layout. The checksums, the data dictionary and E3a's schema all depend on this choice. -> In Data impact, state that `tested` is written only as `audit_tested_control_ia.csv` (no ERM file). Check the other edges for the same problem; the epic's issue-linking rule gives both sources for `against`, so those edges are fine.
3. [minor] INV-9 would be marked as enforced while its test checks only part of it. INV-9 says names "come only from the project's fictional name lists", and the plan replaces its `TBD (E1)` with the AC-4 test. AC-4 checks the name-list columns, and for free text it checks only that nothing matches the deny-list. AI prose can invent a person, vendor or system name that is in no list and not on the deny-list, such as a made-up analyst name or a plausible core-system product name, and AC-4 still passes. The Risks section admits the deny-list "is a floor", but the invariants table would claim full enforcement. -> Either add a check that capitalized multi-word proper-noun sequences in AI text occur in a name list or an allow-list of domain terms, or record in `docs/data-model.md` that the AI-text part of INV-9 is enforced by the deny-list plus the owner's review of the pack, not by the test alone.
4. [minor] AC-7's order check is too weak to mean much at sample size. The check is "the order of matched clusters in risk_erm.csv ... differs from their order in risk_ia.csv". With the minimum of 3 cross-source matches, a random shuffle keeps the same order 1 time in 6. So "differs" fails only on an exactly identical order: a partial shared order (for example 2 of 3 clusters adjacent in the same order) passes, and so does a mostly sorted-by-cluster implementation that happens to swap one pair. The text variant doesn't change row order, so running the check under `--text ai` adds nothing. -> Require independent shuffles in a way the test can see, for example: the Spearman rank correlation of matched-cluster positions between the two files is below a stated bound, or row order is not sorted by internal key in either file. Or require at least 5 cross-source matches so that "differs" carries some signal.
5. [minor] The repo does not ignore `.venv/` or `__pycache__/`. The current `.gitignore` lists only capitan's own files. Slice 1 creates `.venv` in the repo root (as AGENTS.md's install line says), and running the tests creates `__pycache__/` under `tests/`, `akg/` and `src/`. The `__pycache__` folders fall inside the plan's `areas`, so the gate will not flag them if they are committed, and `.venv` is thousands of files outside `areas`. `.gitignore` is governance (rule 8), so the builder cannot fix this. -> Add an owner prerequisite before `capitan start`: add `.venv/` and `__pycache__/` to `.gitignore`. Or have the builder use `.git/info/exclude` locally and say so in the plan.
6. [minor] The plan never says where the committed AI text lives. AC-4 scans "the committed AI text", AC-6 copies it, and slice 6 commits it with input hashes, but the plan gives no path and no format. If the path falls outside `src/features/generator/**`, it is outside `areas`. If it sits next to the output, AC-9's "the README lists nothing the output lacks" becomes ambiguous. -> Name the path and format, for example `src/features/generator/ai_text/<type>.jsonl` with the fields key, input_hash and text, and give it as the default for `--text-dir`.
