VERDICT: REVISE
1. [major] Structure gives the answer away, and AC-4 only tests text. The plan says "A concept instance is a theme applied to one auditable entity ... ERM and IA write each instance in their own voice. Same theme, different entity is the natural hard negative." Today's generator exposes both sources' risks to the same `c.entities` (generate.py, `auditable_entity_exposed_to_risk_*`), and IA's rating equals ERM's 75% of the time. If that carries over, every true pair shares exactly the same exposed entity, and the hard negatives (same theme, different entity) never do. So a matcher that uses "similar text + same exposed entity" would score close to perfect, even though AC-4's TF-IDF-on-text F1 sits in 0.40-0.75. That would make E2's precision and recall (O3) look better than they really are. -> Add a criterion (or extend AC-4) that bounds a structural baseline, e.g. F1 of "same exposed entity set" alone and combined with the TF-IDF threshold. Or say how exposure differs between sources (for example, ERM risks exposed at a broader level, to several entities or a whole business unit; IA risks to one entity) so exposure overlap is a partial cue, not a key.
2. [major] Where full-size AI text is stored, and how the orphan check works, is not specified. There is one `text/ai_text.jsonl` (75 sample entries). `check-text` and a's `test_ac6_missing_stale_or_orphan_ai_text_fails` default to `--size sample`, and `orphan_ai_keys` flags every committed key that the chosen build does not use. Once full-size risk keys are committed, they become orphans at sample size; full size in turn ignores sample control and issue keys. Either a's orphan test breaks, or the epic's rule "a test fails on committed text whose key no item uses" quietly weakens. -> In AC-6, state where full-size text lives (a separate file, or the same file with orphans checked against the union of the sample and full builds), and name the test that keeps the orphan rule at both sizes. Also say whether sample risk keys change format under "natural keys" (they are concept-based today; renaming them would rewrite committed sample text, which touches AC-5 and L-006).
3. [major] The batch path drops L-002's guard, and AC-8's success path is not tested. Today `write_text.rewrite` retries each item inline up to 3 times when `added_systems` finds an invented system. A Message Batch cannot retry inline. AC-8 says "it submits one Message Batch", and the plan does not say what happens to items that fail the check: a second batch (on the same prompt, as L-002 requires), whether that batch is inside the approved budget, or whether a failing item blocks the commit. Also, "measured per-item usage" is not tied to anything in the repo, and the test only covers the refusal half (with a sufficient budget it submits ... and records ... in cost_log.md has no test). -> State that failed items are resubmitted in a follow-up batch with the same prompt, capped by the same `--budget` (and size the owner's approval to include it, e.g. $1.30 plus a retry margin). Commit the measured per-item tokens where the estimator reads them (e.g. in cost_log.md or a constant, with a test that the estimate uses it). Mark the success half as verified by the committed cost_log.md entry and AC-7's check, or reword "one Message Batch".
4. [major] The change cannot finish without an outside decision, and the plan has no fallback. AC-4 (AI variant), AC-6, AC-7 and the full golden in AC-5 all need owner approval of the budget and a batch that has finished. The timebox excludes that wait, but the plan does not say what happens if the owner declines the budget, or if the batch output fails AC-4 (L-002: AI text made matches too easy). Slices 1-2 are self-contained; slices 3-4 depend on outside events. -> Either split now (this change: populations, answer key and difficulty on templated text; a follow-up: batch tooling plus full-size AI risk text), or add an explicit branch: "if the budget is declined or the AI run fails AC-4 after one regeneration, revise to keep full-size risks templated." Also state the order: the `--size full` default flips to `ai` and `checksums_full.sha256` is regenerated only in slice 4, after the text is committed. Until then, `build --size full` with no `--text` flag fails.
5. [minor] Controls change at full size, but no check covers them. "Controls at full size follow risk instances one-to-one with templated text" changes `control_*`, `control_clusters.csv` and their edges at full size. Today's code copies `control_type`, `nature` and `frequency` from the concept into both sources, so matched controls share all 3 attributes. That breaks the epic's "at most 2 of 3 equal" rule (parked in R2's decision for c-e). AC-3 lists only the risk answer-key rules, so it is unclear whether `control_clusters.csv` consistency, which a's helper may assert over "every published control", is expected to hold at full size. -> Say explicitly that control leakage and quotas at full size are child d's, and that AC-3 checks control_clusters coverage and referential integrity only. Or confirm that the shared helper's control rules still pass.
