VERDICT: REVISE
1. [major] The fix for the last critique's identical-rows finding opens a new shortcut that no criterion bounds. The plan now says "Each instance names its entity's context in both sources' wording". IA links each risk to exactly one auditable entity ("IA links a risk to its specific auditable entity"), and entity names are published in `auditable_entity.csv`. If ERM's text carries that entity's name, or a phrase close to it, an obvious E2 blocking rule follows: for each IA risk, keep only the ERM risks whose text mentions the IA risk's exposed entity, then pick the best TF-IDF match. That rule could score far above the 0.80 cap that AC-5 (b) sets for the weaker business-unit filter. The same cue finds within-ERM duplicates: the original and its duplicate share the L3 node, the exposure set and the entity mention, while same-theme siblings differ in the mention. AC-4 bounds only TF-IDF over whole texts and AC-5 bounds only exposure structure, so a build where the entity name decides most matches would still pass. That would inflate the precision and recall O3 publishes. It is also unrealistic: an ERM register written at business-unit breadth does not use IA's audit-universe entity names. -> In Data impact, say that ERM gives the context in its own terms (product, channel or process words, never the audit-universe entity name verbatim). Add an AC-5 (e): an entity-mention baseline (candidates are the ERM risks whose title or description contains the IA risk's exposed entity name, or a distinctive token of it; keep the best TF-IDF candidate above that rule's own best threshold) scores F1 at most 0.80. Measure it at the 2-hour checkpoint along with the same-unit share.
2. [minor] Controls can now be identical rows in one source, which is the same problem the last critique raised for risks. "Controls at full size follow risk instances one-to-one, templated". A control is built from its concept's `ControlConcept` (title, description, type, nature, frequency, systems), so two instances of one theme would give two ERM or two IA controls with the same text and attributes and different IDs, in different clusters. AC-3's new rule covers risks only. Child d resizes controls, but this change commits the full golden output that d's plan will start from. -> Extend AC-3's identical-row rule to controls (title plus description within one source), or state that full-size controls also carry the instance's context in their text.
3. [minor] Within-ERM duplicate difficulty is not measured anywhere. AC-1 sets the duplicate rate (5-10%), but AC-4's bands and hard-negative rate look only at cross-source pairs. At full size, a duplicate and its same-theme siblings in one business unit share the L3 node and the whole exposure set ("ERM links at business-unit breadth"), so only the text tells them apart. Nothing shows whether that is trivially easy (see 1) or impossible. -> Add one bound to AC-4, for example: a within-ERM TF-IDF baseline at its best threshold scores F1 below 0.9, and at least one true duplicate pair scores below the best same-theme non-duplicate pair. Or say plainly that within-ERM difficulty is left to E2 to measure.
