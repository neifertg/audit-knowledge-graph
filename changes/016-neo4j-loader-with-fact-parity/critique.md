VERDICT: REVISE
1. [major] AC-3 now compares only sets, so the INV-8 test no longer checks the invariant as written ("row counts reconcile with node and edge counts"), and it cannot see duplicated edges. On the SQLite side every relationship table has a composite primary key (for example `PRIMARY KEY (audit_id, auditable_entity_id)` in schema.sql), so each row is unique. On the Neo4j side, "the set of (start `id`, end `id`) pairs of edges of its type" collapses two parallel edges into one pair. Nodes are protected by the `id` constraints. Edges are not. Here is a broken loader that passes every named test: it `MERGE`s nodes and `CREATE`s edges, and its step 2 clear silently fails to run. AC-2's "Loading twice gives identical results" is checked through the same set parity, so the second load doubles every edge and still passes. The same goes for a batch accidentally sent twice. -> In AC-3, also assert that each edge type with its endpoint labels and `source` filters has exactly as many edges as its table has rows, and the same for `PLACED_AT`, `MAPS_TO`, `IA_MAPS_TO_ERM` and `REVIEW_CANDIDATE`. Equivalently, compare multisets (`Counter`) instead of sets. Have AC-2's idempotence check use that comparison too.
2. [minor] The mid-load failure test depends on when the loader reads its data, and the plan does not pin that. "A copy of the build whose `akg.sqlite` has one edge table dropped, so the load fails after the nodes" holds only if the loader reads each table while it loads. A loader that reads every row first, which is a natural way to build "the same typed rows", fails before the step 2 clear. The previous load's `LoadComplete` then survives, and the test reports a failure even though the behaviour is safe. -> Either say in AC-2 that rows are read per table during step 4, after the clear, or make the test assert the outcome that matters: the lock is released, the exit is nonzero, and if any entity nodes exist then no `LoadComplete` exists. Also assert that some nodes exist, so the test proves the failure really came midway.
3. [minor] The isolation proof adds another full-size, reconciled build (L-014). `test_batch.full_build` builds `--size full` without `--no-load`, so it reconciles every time. It already runs about 5 times in the suite, and AC-4's check "`test_batch`'s build still succeed[s]" adds one more. -> Count it in the plan. Alternatively, prove `test_batch` and `test_offline` use the shared function by asserting that they pass `env=akg_env()` (for example, all three call sites go through one helper that the unreachable-URI test exercises with a sample build), and keep the end-to-end check on the cheap `run_akg('build', '--size', 'sample', ...)`.
4. [minor] The hermetic helper test says only "a dummy secrets file under a fake home". On Windows, `Path.home()` reads `USERPROFILE`, not `HOME`. CI runs on Linux, where it reads `HOME`. If only one is set, the test reads the owner's real secrets file locally. That fails loudly rather than passing falsely, but it touches real secrets. -> Say that the test sets both `HOME` and `USERPROFILE` (or that the helper takes the secrets path from an override the test sets).
