VERDICT: REVISE
1. [blocker] AC-4 "`akg build` and `akg load` load Neo4j after SQLite when `NEO4J_URI` is set", together with "The whole suite stays the done-check, run once with and once without Neo4j" (and CI always setting `NEO4J_URI`). Many existing tests run a full `akg build` in a subprocess that inherits the environment: `test_determinism` (sample and full, two builds each), `test_issues`, `test_ai_text`, `test_canonical` and `test_sqlite` (sample builds), `test_batch`, and the golden helpers. Under `with_neo4j` or in CI, each of these would (a) wipe and reload the shared Neo4j store, often with a sample or other-seed build, so the "loaded once per test run" seed-42 fixture is overwritten before or between the tests that read it (child c's rounds tests too), (b) add a Neo4j load to every build, which contradicts the plan's L-014 line "the default local suite is unchanged", because the done-check run is not the default, and (c) break `tests/generator/test_offline.py`. That test blocks every socket and fails on unexpected imports, so a build with `NEO4J_URI` set would try to connect and fail. "A build without `NEO4J_URI` never imports `neo4j`" does not cover this, because under the done-check `NEO4J_URI` *is* set. -> Pin how test builds stay off Neo4j. For example, `run_akg` and the other subprocess builds drop `NEO4J_*` from the child environment unless a test opts in, or builds get an explicit `--no-neo4j` flag. The offline test runs its build with `NEO4J_URI` removed. Put `tests/generator/helpers.py` and the offline test in the slices, and add a criterion that the full suite passes under `with_neo4j` with only the Neo4j tests touching the server.
2. [major] AC-2's lock steps contradict each other: "1. Take the load lock: a single `LoadLock` node ... 2. Clear the database (`CALL (n) { DETACH DELETE n } IN TRANSACTIONS`)". Clearing every node deletes the lock itself, so a concurrent load sees no lock for the whole load, and "5. Release the lock" has nothing to release. The plan also does not say that acquisition is atomic: check-then-create in two statements lets two loads both see "no lock". And it does not say the lock is released when a load fails, so a crashed load blocks every load for 10 minutes. -> Clear with `MATCH (n) WHERE NOT n:LoadLock`. Take the lock atomically: a uniqueness constraint on `LoadLock`, created before step 1, plus one `MERGE`/`CREATE` in a write transaction that also replaces a stale lock. Release in `finally`. Make AC-2's test observable: a fresh lock makes `load_neo4j` raise and leaves the graph untouched; an 11-minute-old lock is replaced and the load succeeds; after a forced mid-load failure no lock remains.
3. [major] AC-1's node rule is wrong as written: "every table with a `primary key` column is a node type ... These are the published entities plus `CanonicalRisk` and `CanonicalControl`." `reconciled/ia_maps_to_erm.csv` has `ia_node_id` as its primary key (see `reconciled_dictionary.md`). By the stated rule it becomes an `IaMapsToErm` node label, yet the same criterion maps it to `IA_MAPS_TO_ERM` edges and IA-node properties. The prototype excluded it by name. AC-1's test "for all 47 tables" cannot pass both readings. -> State the exclusion explicitly ("except `ia_maps_to_erm`, mapped as below"). Have AC-1's test pin the exact label set and the 16 entity tables that make nodes, so the 2,821 figure has a precise definition.
4. [major] AC-3 relies on counts plus "One deterministic sample row per table, the lowest key". A loader that swaps edge direction or endpoints within one label still passes: `PARENT_OF` (TaxonomyNode to TaxonomyNode), `AGAINST`, or a `REVIEW_CANDIDATE` loaded `item_b -> item_a` all keep their counts, and the lowest-key row catches it only if the sample compare checks direction. That is exactly the drift INV-8 exists to rule out, and later rounds rely on direction (paths, `PARENT_OF` recursion). -> At 10k rows it is cheap to compare, per table, the full set of key tuples: `(from_id, to_id)` for edges with their endpoint labels and `source`, and `id` sets for nodes. Keep the one-row property sample for values.
5. [major] AC-3's value comparison ("has equal values in both stores") has no rule for NULLs. `SET n = r` drops null keys, so blank `issue.closed_date`, blank maps-to `logit` and NULL `canonical_risk` columns are absent properties in Neo4j and NULL in SQLite. The rule for REAL versus float equality and for `int` columns is also unstated. -> Pin it: NULL in SQLite equals an absent property, and decimals compare exactly, because both come from the same SQLite value. Choose sample tables, or a sample rule, that exercise at least one NULL (for example the lowest issue with a blank `closed_date`, and an unmerged maps-to row).

[major] AC-4's `with_neo4j` helper reads `~/.claude/secrets.yaml`, and "Both paths are tested" plus "It never prints them" are to be proven in a suite that CI runs, where no secrets file exists and pull-request jobs must never get secrets. The plan does not say the helper's test is hermetic. -> The helper's test points the helper at a temporary secrets file, through a fake home (`USERPROFILE`/`HOME`) or a documented override variable holding a dummy password. It asserts that the child sees the three variables and that the dummy password appears in neither stdout nor stderr. It also asserts a clear error when the file or `databases.akg_neo4j` is missing. The test never reads the real file.
7. [minor] Error behaviour of the pipeline is unpinned. What do `akg build` and `akg load` do when `NEO4J_URI` is set but the server is down, auth fails, or `akg.sqlite` is missing? A half-finished Neo4j load also leaves a partial graph with nothing marking it, unlike SQLite's `.partial` rename. -> State that the command exits non-zero with a one-line message and leaves `akg.sqlite` intact. Optionally record completion, for example a `LoadLock`-style `LoadComplete` marker excluded from counts, that later rounds check. Otherwise say that rounds rely on the parity test alone.
